# Linux Local Studio Application

- Rust + GTK4 + libadwaita. Links `core/` (`local-studio-core`) as a plain crate: no UniFFI, no C ABI.
- `linux/` is its own Cargo workspace (own `Cargo.lock`), outside the root one, so `cargo clippy --workspace` on macOS never needs GTK. The core's `../eukhe` path dependencies still resolve from the root.
- Dev shell (Rust 1.98.1, Zig 0.15 for the core's libghostty-vt, GTK 4.22, libadwaita 1.9, WebKitGTK 6, GStreamer for notification sounds, clang, xvfb-run, dbus, fonts, icons): `nix develop ./linux` in a git checkout, `nix develop path:linux` in a plain copy. Run the commands below from `linux/` inside it. Point `ZIG_GLOBAL_CACHE_DIR` at a scratch directory on shared machines.
- Build: `cargo build` → `target/debug/local-studio`.
- Lint: `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check`. Same bar as the rest: no `unsafe`, `unwrap`, `expect` or code comments.
- Daemon: the app starts `$EUKHE_DAEMON`, else `eukhe-daemon` beside the binary, else the one on `PATH`, on `$EUKHE_DAEMON_SOCKET` (default `/tmp/eukhe-<uid>/daemon.sock`). Build one with `cargo build -p eukhe-daemon -p eukhe-cli` in `../eukhe`.
- Python kernel: the core manages it through the `eukhe` CLI beside the daemon (`eukhe kernel install --check` at launch, `eukhe kernel install` in the background when missing; uv downloads Python, so it needs uv on `PATH` and network). Progress and failures (with Retry) show in a banner; Settings → General → Diagnostics → Python kernel shows the state and Install/Retry. The daemon and CLI find `eukhe-runtime/` beside themselves (Eukhe's release layout) or, run from an eukhe checkout's `target/`, in that checkout.
- Packaging: `nu bundle.nu [--profile debug|release]` (after `cargo build`) assembles `target/<profile>/bundle/` in Eukhe's release layout: `local-studio`, `eukhe-daemon` and `eukhe` (`$EUKHE_DAEMON` or `../eukhe/target/{release,debug}`), `eukhe-runtime/` and `skills/` from the eukhe checkout holding the daemon (release exclusions), and `share/local-studio/controller/`. Run `bundle/local-studio` without `EUKHE_DAEMON`.
- Keybindings come from the core (`Update::Keybindings`, mapped in `src/bindings.rs`); `cmd` maps to Ctrl. Focus regions, recent-thread cycling and list keys live in `src/keyboard.rs`, the composer's vim engine in `src/vim.rs` (`Settings.vim_mode`). Composer and header choices use the shared popover in `src/picker.rs`, not GtkDropDown. Terminals live in the bottom drawer (`src/drawer.rs`) and run in the core (libghostty-vt): `src/terminal.rs` draws `Update::TerminalFrame` rows with Pango and sends keys (XKB hardware keycodes), mouse, scroll, paste and focus back through the core encoders. While a terminal has focus, app accelerators are suspended and the drawer takes Ctrl+Shift+T/D/E/W/C/V/A instead of the `terminalFocus` bindings.
- Providers (Settings → Providers, `src/providers.rs`) go through the core's providers service: keys with `set_provider_key`, custom endpoints with discovery and add/update/remove/refresh, fleet engines with `use_local_engine`. The Local page (`src/dashboard.rs`) watches the selected machine with `watch_local_dashboard` while it is visible; machine management lives in Settings → Local (`src/fleet.rs`).
- Client-only preferences (favorite editor, composer stash, sidebar width) live in `$XDG_CONFIG_HOME/local-studio/linux.ini` (`src/prefs.rs`); everything shared goes through core `Settings`, including custom themes (`Settings.custom_themes`, JSON).
- Colors come from `src/colors.rs`: the default palette (dashboards) and the built-in `gildrb` theme (dark and light, follows the color scheme). CSS, code highlighting (`src/highlight.rs`), diff tags and the terminal palette all read the current `Colors`; add new colored surfaces there, not as literals.
- Assistant text and pull request bodies render through `src/markdown.rs`: one non-editable GtkTextView per text block (blocks are TextTags, code keeps the syntax tags, links open on click), cached per transcript item so streaming updates refill the same view. Ctrl+C copies exactly the visible selected text like macOS `MarkdownCopy`: list markers as shown (`•`, `1.`, nested items indented by tabs), code without fences or its language header, table cells separated by tabs, no `#`/`>`/`---` Markdown markers, a blank line between blocks.
- Headless runs use isolated state and the real model (`anthropic/claude-haiku-5-5`, thinking `low`; root `AGENTS.md`): link `auth.json` from a logged-in agent dir on the same machine (never copy it), copy the rest with the agent `settings.json`'s `defaultProvider`/`defaultModel`/`defaultThinkingLevel` set to that model (`--smoke` checks the empty-thread composer shows the daemon's default and fails if it is another model), run, remove the link:
  ```sh
  mkdir -p /tmp/X/home /tmp/X/agent && ln -s "$(realpath <creds>/auth.json)" /tmp/X/agent/auth.json && install -m 600 <creds>/{models,settings}.json /tmp/X/agent/
  env HOME=/tmp/X/home LOCAL_STUDIO_DATA_DIR=/tmp/X/data EUKHE_CODING_AGENT_DIR=/tmp/X/agent \
    EUKHE_DAEMON_SOCKET=/tmp/X/d.sock EUKHE_DAEMON=<eukhe-daemon> \
    GDK_BACKEND=x11 GSK_RENDERER=cairo xvfb-run -a -s '-screen 0 1600x1000x24' dbus-run-session -- target/debug/local-studio --smoke
  rm /tmp/X/agent/auth.json
  ```
  - `--smoke`: adds a project, starts a supervised thread on the real model through the composer, approves its bash call, and requires the call's output and file (`smoke.txt`) plus the streamed reply in the timeline, then sends a follow-up (drawn at once as a local bubble, replaced by the core's user item, answered by the real model) and a send the core rejects (bubble removed, text back in the composer), then resolves an `@` mention, lists the project in the Files surface, runs a thread content search, types a command into a drawer terminal and waits for its output, and adds that output to the composer with Add to Chat. Then it checks Ctrl+T and vim `dw`/`dd`/`u` in the composer; prints `PASS linux smoke` and exits 0. It never writes `auth.json`. Set `SHELL` to bash for it.
  - `--smoke-kernel [install|installed|offline]`: run from `bundle.nu`'s bundle without `EUKHE_DAEMON`. `install` needs a fresh `HOME` (no `~/.eukhe/kernel-venv`): the launch must install the kernel, then a real ipython call ("list the files here and count them with Python") must succeed with no "not installed" error; `installed` on the same `HOME` must not install again and runs the same request. `offline` runs on a fresh `HOME` with no uv on `PATH` and `LS_SMOKE_UV=<uv binary>`: the launch's install must fail, the same request must show exactly one kernel warning notice row and no ipython call, then the smoke links uv into `$HOME/.local/bin`, presses Retry (`win.install-kernel`), and a new thread's ipython call must succeed. Prints `PASS linux smoke: kernel: …`.
  - `--smoke-providers`: with `LS_SMOKE_PROVIDER=http://127.0.0.1:<port>/v1` (the core's `provider_stub` example started with the key `smoke-key`) it discovers, adds and removes a custom endpoint through the endpoint dialog. It saves keys, so run it on a scratch agent dir with its own `auth.json` (`{}`) and `models.json` (`{"providers":{}}`), never a linked one; it needs no model login. Before anything starts it refuses (`FAIL`, exit 1) when `EUKHE_CODING_AGENT_DIR` is unset, its `auth.json` is a symlink, a hard link or holds keys, or the dir resolves into a real agent dir (`.pi`, `.eukhe`); it fails if any key is left in `auth.json` at the end.
  - `--snapshot <dir> [name-filter]`: renders every fixture scene (`fixtures::scenes()`: `src/fixtures.rs`, `src/scenes*.rs`, `src/dashboard_scenes.rs`, `src/keyboard.rs`) offscreen to `<dir>/<scene>.png`, open popovers included; needs no daemon. Look at the PNGs after UI changes.
  - `LOCAL_STUDIO_SNAPSHOT_LIVE=1` adds the `usage-live*` scenes (`src/usage_scenes.rs`): they start the core against the daemon on `$EUKHE_DAEMON_SOCKET`, load the real usage report from its saved sessions and render the Usage page (30 days tokens and cost, 24 hours, gildrb, limits; dark and light). Point the daemon's `EUKHE_CODING_AGENT_DIR` at a scratch copy of the sessions.
  - Stop the daemon afterwards from the repo root: `cargo run --example smoke -p local-studio-core -- --stop /tmp/X/d.sock`.
- Never stop processes this app did not spawn.
